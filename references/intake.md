# 需求采集与主题锁定（Intake）

> 本文件回答一个问题：用户说「帮我做个卡点视频」之后，这条片**做成什么样**。
> 读它的时机：调用本技能后的第一个动作，先读本文件 + `templates/themes.js`，再动手。
> 采集结果写成项目根目录的 `brief.json`；后续阶段只读它，不再反复问用户。

---

## 0. 铁律

1. **不要直接开做。** 先收信息 → 锁定主题配色 → 落 `brief.json`，才允许写剪辑表、渲染任何一帧。
2. **最多 2 轮对话。** 第 1 轮给默认方案 + 问必问项；第 2 轮锁定主题并确认。用户不答的项用默认值，在 `brief.notes` 里标 `default`，不要追问第 3 轮。
3. **主题先锁定。** 主题决定整片骨架色、材质与 HUD；没锁定主题就渲染 = 全片返工。
4. **只从 8 套主题里选。** 不要自创第 9 套，也不要为单支片改 `templates/themes.js` 的公共色值；用户想改主色只记录 `theme.accentOverride`。

---

## 1. 两轮怎么问

**第 1 轮**（一条消息内完成，不要拆成 8 条）：

- 先给默认方案：`默认按 61s / 1920×1080 横屏 / 11 个风格段 / 珊瑚暗夜 / 120BPM 电子配乐起一版，你只需要确认 4 件事。`
- 发主题预览图（见第 3 节），让用户先看图再选；
- 只问必问 4 项：用途/题材、发布渠道/画幅、品牌名、结尾 CTA。时长、风格数、配乐只在用户主动提时才展开。

**第 2 轮**：

- 复述已确认项 + 默认项，锁定主题 id，说清主题中文名；
- 用户对主题犹豫时只推荐 2 套（带图 + 一句理由），不要报菜名式列 8 套；
- 输出 `brief.json`（第 5 节）写到项目根，宣布「主题锁定：<中文名>（<id>），后续渲染都用它」。

**可跳过第 2 轮**：用户第 1 轮就说清主题 id/名称、渠道/画幅与 CTA，直接落 brief 并宣布锁定。

## 2. 必问清单（8 项）

| # | 问什么 | 默认值 | 用户说「随便」/不回答时 |
|---|---|---|---|
| 1 | 题材/主题：这条片讲什么、给谁看 | **无默认，必须问** | 再追问一次；仍不答，就按品牌/行业代拟 3 个选题让用户点一个 |
| 2 | 品牌名：真实品牌还是占位 | `{{BRAND}}`（全片唯一替换点） | 用 `{{BRAND}}` 占位，交付前提醒替换；真实品牌要确认中文/英文写法、水印是否要 logo 文字 |
| 3 | 时长：30–90s | 61s（=1830 帧 @30fps） | 61s |
| 4 | 画幅：横屏还是竖屏 | 1920×1080 横屏 | 横屏，并说明竖屏要重排全部片段 |
| 5 | 风格数 N：6–11 | 11 | 11；若时长已定，按 `N = floor((D-17)/4)` 反算并夹到 6–11 |
| 6 | 主题配色：8 选 1 | `coral-noir` 珊瑚暗夜（原版） | `coral-noir`，同时把预览图再发一次确认 |
| 7 | 结尾 CTA：一句话 | `关注 {{BRAND}}`（无二维码） | 品牌名 + 一行 CTA，`hasQr=false` |
| 8 | 配乐偏好：电子/克制/史诗/轻快/国风 | 120BPM A 小调电子 | 默认电子；只换乐器与编曲密度，**BPM 不动** |

### 2.1 时长、N 与结构的关系

`总时长 D = 开场 O + N×4s + 「还有更多?」1s + 八连闪 2s + 结尾 E`，默认 `O=8, E=6` ⇒ **`D = 17 + 4N`**。

- N=11 → 61s（默认，样片验证过的配比）；N=6 → 41s；
- 30–40s 属于极限压缩：只能 N=6 + 开场 4s + 结尾 4s + 八连闪 1.5s ≈ 34.5s；再短就放不下 6 个风格段，不建议；
- 90s 需要把开场/结尾各拉到 12–14s，或让部分风格段变 6s 双段轮播——先确认用户真的需要，否则按 61s 交；
- 时长一旦确定，帧数 = `round(D×30)`，全片必须对得上（默认 1830）。

### 2.2 竖屏的额外成本

- 大字卡与胶囊/倒计时位置全部重排，关键词最大字号按短边换算（约 ×0.7）；
- 11 个风格段都要按 9:16 重新构图，03 发布会、05 赛博、07 数据、11 竖屏的改动最大；
- 工期按横屏的 1.2–1.3 倍估；先跑 1 段样板让用户确认，再铺开。

## 3. 主题配色：8 选 1

### 3.1 怎么给用户看

- 先发 `assets/theme-previews/theme-three-up.jpg`（3 套并排，最快建立印象），再发 `assets/theme-previews/theme-contact-sheet.jpg`（8 套总览）；
- 用户点名想看某套时发单主题图：`assets/theme-previews/01-coral-noir.jpg` … `08-crimson-theater.jpg`；
- 每套配一句话说调性（下表），不要只发图不解释，也不要一次摊 8 张细节图；
- 预览图是「主题板」：看色、看材质、看气质，**不是**成片构图参考。

### 3.2 一句话调性 + 选型矩阵

| # | 主题 id | 名称 | 一句话调性 | 适合 |
|---|---|---|---|---|
| 01 | `coral-noir` | 珊瑚暗夜 | 温暖暗场 + 珊瑚一点，原版电影感 | 默认 / 科技发布 / 产品片 |
| 02 | `claude-light` | 橙光白 | 暖纸底 + 陶土橙，像一页印好的信 | 品牌 / 知识 / 访谈（Claude 品牌自有色，按「品牌自有例外」处理） |
| 03 | `aqua-morandi` | 水蓝白·莫兰迪 | 雾面水色，淡绿与淡粉只从光里透出来 | 美妆 / 生活方式 / 轻科技 |
| 04 | `amber-noir` | 琥珀黑金 | 近黑与旧金，片头字幕的质地 | 高端 / 奢品 / 年度片 |
| 05 | `blueprint-stone` | 蓝图纸 | 石色纸 + 蓝图钴蓝，工程档案 | 工程 / 建筑 / 数据 / 技术 |
| 06 | `graphite-signal` | 石墨信号 | 石墨灰 + 安全橙，工业硬核，没有光晕 | 开发者 / 硬件 / 工业 / 硬核科技 |
| 07 | `celadon-paper` | 青瓷白 | 整片只有一种深青，像瓷器上的釉 | 东方 / 文化 / 极简 / 品牌故事 |
| 08 | `crimson-theater` | 绯墨剧场 | 近黑与绯红，舞台聚光的戏剧 | 时尚 / 艺术 / 预告 / 情绪片 |

**选型矩阵**（用户说用途后先查表，再带图确认）：

- 科技发布 / 产品片 → 珊瑚暗夜 或 石墨信号（前者更暖更电影，后者更硬更工业）
- 品牌 / 知识 / 访谈 → 橙光白
- 美妆 / 生活方式 / 轻科技 → 水蓝白·莫兰迪
- 高端 / 奢品 / 年度片 → 琥珀黑金
- 工程 / 建筑 / 数据 → 蓝图纸
- 东方 / 文化 / 极简 → 青瓷白
- 时尚 / 艺术 / 预告 → 绯墨剧场
- 完全没方向 → 珊瑚暗夜（原版、暗场容错高）；想要浅色品牌感就橙光白

### 3.3 用户没主意时怎么推荐

只推荐 2 套，各配一张单主题图，理由一句话：

- 泛需求：`珊瑚暗夜`（原版配比最稳、信息层次最好、暗场不挑内容）+ `橙光白`（浅色品牌感，适合知识/访谈/生活方式）；
- 行业明确的片子：从 3.2 矩阵挑同类别两套（硬件 → 石墨信号 vs 珊瑚暗夜；东方品牌 → 青瓷白 vs 橙光白）。

### 3.4 改主色的边界

- 只允许改「强调色」：调 `templates/themes.js` 的 `accentOverride(themeRef, input)`（字符串 = 只换 `accent`，或 `{ accent, accentInk, accentSoft }`），它会自动挑对比度 ≥ 4.5 的 `accentInk`、算 `accentSoft`、同步材质光晕与 HUD 编号；把返回对象里的 `override` 原样写进 `brief.theme.accentOverride`，整片统一替换一处，不要逐段改；
- 换底色/换材质/换字体不属于主题系统：要么在 8 套里换一套，要么明确告诉用户超出「换主题」范围、需要额外工期；
- 不要自创第 9 套主题，也不要改 `templates/themes.js` 的公共色值。

## 4. 「信息够了」的判定

**必须追问（缺一不可）**：

1. 视频用途/题材；
2. 发布渠道或画幅；
3. 品牌名（真实名，或用户明确接受 `{{BRAND}}` 占位）；
4. 结尾 CTA。

**可以给默认（写进 brief 并在 `notes` 标 default）**：时长、fps、风格数 N、主题配色（推荐后用户默认接受）、配乐偏好、二维码、字体/编码参数。

- 判定通过 = 4 项必问齐全 + 主题 id 已确定；此时才写 `brief.json`，进入剪辑表阶段。
- 用户中途改主题/改时长：只更新同一份 brief 并重渲受影响部分（见第 7 节），不要开第二份 brief。

## 5. BRIEF.json（模板，直接复制改值）

```json
{
  "project": {
    "name": "brand-style-showcase",
    "topic": "用纯代码做一支卡点片",
    "brand": "{{BRAND}}",
    "deliverable": "61s 横屏 MP4（1920×1080）+ 封面帧 + 参数说明"
  },
  "duration": 61,
  "fps": 30,
  "size": { "w": 1920, "h": 1080 },
  "aspect": "16:9",
  "styles": [
    { "no": 1, "title": "扁平插画科普", "recipe": "01 扁平插画科普" },
    { "no": 2, "title": "数学动画", "recipe": "02 数学动画" },
    { "no": 11, "title": "竖屏短视频", "recipe": "11 竖屏短视频" }
  ],
  "theme": { "id": "coral-noir", "accentOverride": null },
  "ending": { "cta": "现在就试试 {{BRAND}}", "hasQr": false },
  "music": { "style": "electronic", "bpm": 120 },
  "notes": "[default] duration=61s / N=11 / music=electronic；不出现真人镜头"
}
```

字段说明（每个字段一行，示例值见上面 JSON）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `project.name` | string | 项目名，也作输出文件名根 |
| `project.topic` | string | 题材一句话，决定大字卡文案与风格段取舍 |
| `project.brand` | string | 品牌名；未定用占位 `{{BRAND}}`（全片唯一替换点） |
| `project.deliverable` | string | 交付物描述：时长/画幅/额外产物 |
| `duration` | number | 成片秒数，默认 61（必须与剪辑表帧数一致） |
| `fps` | number | 帧率，固定 30 |
| `size` | object | 像素尺寸 `{w,h}`，横屏 1920×1080 / 竖屏 1080×1920 |
| `aspect` | string | 画幅比例 `16:9` / `9:16`，决定大字卡安全区 |
| `styles` | array | 风格段清单，顺序 = 剪辑顺序；`recipe` 指向 `references/style-recipes.md` 的段落标题 |
| `theme.id` | string | 主题 id（`templates/themes.js` 的 key），渲染时拼 `?theme=` |
| `theme.accentOverride` | object\|string\|null | 只覆盖强调色；填 `accentOverride()` 返回的 `override`（或直接填一个 hex 字符串），无覆盖填 `null` |
| `ending.cta` | string | 结尾一句话 CTA |
| `ending.hasQr` | boolean | 结尾是否留二维码位 |
| `music.style` | string | `electronic` / `restrained` / `epic` / `upbeat` / `guofeng` |
| `music.bpm` | number | 默认 120；只换乐器不动 BPM，改 BPM 要重算全片时间 |
| `notes` | string | 默认值标注、用户特殊要求、禁忌（如「不出现真人镜头」） |

## 7. 交接与下游消费

- **落盘位置**：`brief.json` 放项目根（与项目 README、剪辑表同级），不要塞进脚本常量。
- **下游怎么读**：剪辑表、`templates/segment.html`、`templates/big-card.html` 只读 `brief.theme.id` 拼页面 URL `?theme=<id>`（别名由 `themes.js` 解析）；不传 theme = `coral-noir`，与旧视觉一致。
- **覆盖值的消费**：若 `brief.theme.accentOverride` 非空，下游先 `accentOverride(getTheme(brief.theme.id), brief.theme.accentOverride)` 得到最终主题对象，再传给 `chrome()` / `cardColors()` / `drawThemeBackground()`；不要把它当成第 9 套主题。
- **锁定后写一行**：在项目 README 或项目笔记里写 `本项目主题：<中文名>（<id>）` + `brief.json` 路径，方便交接和改片。
- **改主题的成本**：剪辑表/文案/音轨都不动，重渲片头 + 12 张大字卡 + 11 个风格段 + 八连闪 + 结尾（等于全片重渲，但不用重做结构）。
- **与主题绑定**：背景材质、大字卡四版式的 bg/ink/echo/grid、胶囊/倒计时/水印、风格段的换色与染色、结尾大色场、闪白颜色。
- **与主题无关**：时间结构、剪辑表、风格配方本身、配乐编排、编码参数。

## 8. 常见误用（反面清单）

1. **一次问 8 个问题** → 用户流失。先给默认方案，只问关键 4 项。
2. **没锁主题就渲染** → 全片返工。主题必须先落进 `brief.json`。
3. **一支片混用多套主题**（每轮换一个）→ 变成调色板演示，不是风格片。一支片只用一个主题，风格差异靠分段配方 + `theme.accents`。
4. **自创第 9 套主题 / 把单支片色值改进 `themes.js`** → 污染公共资产。只记 `theme.accentOverride`。
5. **把预览图当构图参考** → 预览是主题板；构图按 `references/big-card-and-typography.md` 与 `references/style-recipes.md`。
6. **竖屏直接套横屏坐标** → 胶囊、大字卡、倒计时全错位。
7. **用户说「随便」还反复追问** → 直接用默认值，并在 `notes` 标 `default`。
