### 0.2 五条结论

1. **默认路径产出的片子不能直接交付。**
   开场/结尾是 `风格段标题` / `替换 drawScene() 开始做真正的画面`，卡片页脚是 `{{BRAND}}`；仓库自带 fixture 的 10 个页面引用里 8 个指向占位页，41 秒片中 32 秒是同一张占位画面。**3 个角色独立命中**（T01 / T02 / T05）。

2. **三种「成功但错」比报错更危险。**
   `build` 不跑 lint（未知主题静默回退并出片）；QA 只验容器（占位页拿 10 pass / 0 fail）；`--resume` 只比帧数（改了文案仍跳过，还把旧 mp4 以新 hash 写回缓存）。**3 个角色独立命中**（T03 / T04 / T05）。

3. **交付链条断在最后一公里。**
   默认静音（`--audio` 才混音）、无字幕、`render.preset` 只写不读、变体共用 `outDir` 互相覆盖、回滚只回 JSON 不回 mp4。

4. **对 Agent 的契约是「导演手册」，不是「执行契约」。**
   两套入口（spec vs timeline）、两套产物名（master vs final）、两套 QA 严格度（build 不带 `--strict`）、90–116 个 `E_*` 码里只解释了 2 个、SKILL 37 KB≈9k tokens。

5. **定位必须二选一。**
   今天能独立走完「安装→出片」的只有「带 Agent 且有 Node/Chrome/FFmpeg/Python 的开发者」。路线图写的「小白选两下出片」和品牌运营需要的「投放交付」都还没有最后一公里。

## 1. 方法与可信度

### 1.1 取样纪律

- **独立取样**：7 个角色互不通信，避免意见互相污染；每个角色只看自己画像关心的面。
- **证据门槛**：每条必须有 `path:line` 或真实命令输出（含 exit code / stderr 片段）；无证据的判断强制 `confidence ≤ 4`。
- **禁止项**：不得改产品代码、不得 `git commit`、不得跑全量测试与真实渲染（个别角色为验证断言跑了 `--dry-run` / 单套件）。
- **聚合规则**：同一根因跨 ≥3 角色 → 升一级；`impact × frequency × confidence ÷ 工时权重`（S=1/M=2/L=4/XL=8）得 ICE 分。

### 1.2 抽检（发布前复核，8/8 属实）

### 1.3 已知偏置（诚实边界）

- 6 名内测者都是**读码 + 局部命令**，没有完整跑一次 41 秒渲染（成本与时间约束）；涉及「成片观感」的结论来自 fixture 产物与作者既有成片，不是本轮新渲。
- T01（小白）与 T02（品牌）的 P0 严重度建立在**各自画像**上；若产品明确只服务 Agent，他们的 P0 应降级为「路线缺口」而非「当前阻断」。
- `E_*` 码数量因 grep 作用域不同有 90（scripts/templates/bin/server）与 116（+ingest/app）两种口径，报告统一写「90–116」。

### 3.1 三个最值得警惕的模式

1. **「配置写了但没人读」** —— `render.preset`（6 平台）、`audio.vo`、`meta.cta`、`brandKit.logo/fonts`、`motion-profile` 的 6 个字段、`transitionParams()`、`drawKineticText()` 全是「声明存在、消费为零」。这是**承诺漂移**，比缺失更伤信任。
2. **「绿灯只证明没崩」** —— QA 的 10 项断言全是容器级；音频 QA 的分母只算「已对齐」的 cue；`W_BRAND` 只是 warning。三者叠加，**占位片 + 静音片 + 拼错主题的片都能一路绿灯交付**。
3. **「默认路径是开发者路径」** —— 默认 spec 的文案、默认 fixture 的页面、默认 CLI 的 help、默认 wizard 的状态条，全是写给作者自己的。终端用户拿到的第一份产物就是「工程占位符」。

## 5. 复跑这个集群

本集群可复用，不依赖本次会话：

1. **编制与协议**：`docs/feedback/PERSONAS.md`（7 个角色卡 + 统一反馈模板 + 聚合规则）。
2. **并行取样**：每个角色一个独立 Agent/worker，读 `PERSONAS.md` 的 §0 与自己的段落，只写 `docs/feedback/inbox/<NN>-<role>.md`。
3. **聚合**：PM 按根因聚类（不按角色合并）、ICE 打分、跨角色加权，产出 `OPTIMIZATION-PLAN-*.md` + `BACKLOG.json`。
4. **门禁**：`all_inboxes_present` → `cross_role_dedup_done` → `every_item_has_evidence` → `plan_scored_and_sequenced`。
5. **台账**：`.cluster/state.json` 记录基线 commit、角色状态、产物路径与门禁结果。
