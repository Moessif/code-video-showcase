# 内测集群编制 · code-video-showcase v2.3.4

> 目的：用 1 名产品经理 + 6 名异质内测者，在同一基线上独立取样，产出**可去重、可打分、可排期**的意见池。
> 纪律：内测者只允许写 `docs/feedback/inbox/`，不得改产品代码、不得 git commit、不得跑全量构建或长时间渲染。

## 0. 统一反馈协议

每条意见必须是一个**可验收的条目**，禁止「体验一般」「建议优化」这类空话。格式：

```markdown
### F-<角色编号>-<两位序号> <一句话标题>
- 严重度: P0 阻断 / P1 严重摩擦 / P2 明显不便 / P3 打磨
- 证据: <path:line> 或 <命令 + 真实输出片段（≤6 行）>
- 我的原话: 「作为<角色>，我在这里想<目标>，但<发生了什么>」
- 影响面: 谁会遇到 / 多频繁（每次必踩 / 特定场景 / 极少）
- 建议方案: 具体到改哪里、加什么字段/命令/文案
- 验收断言: Given ... When ... Then ...（可机械判定）
- 工作量: S(<0.5d) / M(0.5–2d) / L(2–5d) / XL(>5d)
- 打分: impact 1-10 / frequency 1-10 / confidence 1-10
```

排序纪律：先写 P0，再写 P1；同一问题不要拆成多条刷数量；**每条最多 12 行**。

## 1. PM-00 产品经理（聚合角色）

- 视角：定位、用户分层、留存与二次修改率、路线图与 `docs/CLUSTER-PLAN.md` 的偏差、分发与商业化。
- 只回答三个问题：**为谁做、凭什么留下、下一步砍什么**。
- 产出：产品层判断 ≤6 条（含 1 条「最该砍的功能」），不与内测者重复报 bug。

## 2. T01 小白短视频创作者（无技术背景）

- 画像：会剪映，不会 Node；目标是「今晚发一条 30 秒竖屏宣传片」。
- 起点：只读 README 前 80 行 + `node bin/cvs.mjs --help` + wizard 相关代码。
- 关注：5 分钟内能否出片、默认值是否合理、报错是否人话、失败后能否自己救回来。
- 必答：**如果我是第一次打开这个仓库，我会在哪一步放弃？**

## 3. T02 品牌 / 市场运营

- 画像：管品牌规范与多平台投放，一天要出 3 个尺寸、2 个版本。
- 关注：品牌色是否真的进片、平台规格、批量变体、封面/文案资产、审片与回滚。
- 必答：**这套东西能不能替掉外包的「改一版」环节？**

## 4. T03 独立开发者 / 自托管工程师

- 画像：会读源码，要接 CI、要可复现、要错误码。
- 关注：CLI/API 契约、退出码与错误码、确定性、依赖与安装体积、Windows 路径、日志可观测性。
- 必答：**我能不能把它塞进 GitHub Actions 并在失败时知道为什么？**

## 5. T04 Agent 用户（Claude Code / ZCode 装载技能）

- 画像：不手敲命令，让 Agent 读 SKILL.md 自己干。
- 关注：触发词覆盖、指令歧义、token 成本、失败自愈路径、`allowed-tools` 与安全边界、可验证的完成定义。
- 必答：**Agent 读完 SKILL.md 后，最可能做错的一件事是什么？**

## 6. T05 职业剪辑师 / 动效师

- 画像：习惯 Premiere/AE，关注节奏与可控性。
- 关注：时间轴控制粒度、转场与关键帧、音频混音、QA 报告是否可信、成片是否「一眼模板味」。
- 必答：**给我什么，我才愿意用它而不是 AE？**

## 7. T06 企业内网 / 离线集成方

- 画像：无外网、有安全审计、要版本锁定与升级路径。
- 关注：离线可用性、字体与许可、CDN/远程资源、端口与 CORS、spec 作为不可信输入的防护、审计与回滚。
- 必答：**过安全评审时，哪一条会被卡住？**

## 8. 聚合规则（PM 执行）

1. 同一根因跨 ≥3 个角色出现 → 升一级优先级，记 `cross=3`。
2. `impact×frequency×confidence / effort权重`（S=1, M=2, L=4, XL=8）得 ICE 分。
3. P0 无条件进「本轮必修」；P1 按 ICE 排序进「下一里程碑」；P2 进「打磨池」；P3 只登记。
4. 每条优化项必须绑定：证据、验收断言、负责面（入口/编译/渲染/质检/文档）、预估工时。
